## Anti-Patterns Verdict

**Does this look AI-generated? No.** This reads as a deliberate educational instrument in the GeoGebra/Tinkercad lane, not a generic SaaS template.

**LLM assessment:** None of the absolute bans are present: no gradient text, no glassmorphism, no side-stripe borders, no hero-metric template, no identical card grids, no modal-first thinking. Chrome is genuinely quiet and the 3D viewport is the loud subject, exactly as the strategy demands. The one "subtly off" tell a careful eye catches is the **blue chrome accent sharing a hue with the blue HP projection line** — a functional domain color colliding with the guidance color.

**Deterministic scan:** Unavailable. `detect.mjs` ran but reported `bundled detector not found` (exit 1), so the automated pass could not run. This verdict is from manual review + browser screenshots only.

**Visual overlays:** Not injected. Reviewed via captured screenshots of all five steps rather than an in-page overlay.

## Overall Impression

This is a confident, restrained teaching tool that already nails the hardest part: the guided arc reads clearly, the viewport dominates, and the warm-paper calm fits the "patient tutor" personality. The biggest opportunity is not structure, it is **fidelity to your own DESIGN.md** plus **support for the single user you optimize for** (the anxious first-year): the palette drifted from the contracted indigo/teal/amber into a blue-on-blue collision, and the inline term definitions + orbit discoverability that the struggling learner most needs are absent.

## What's Working

1. **The guided arc is legible and honest.** Empty start → add → incline → label → project → flatten is a real pedagogical sequence, the rail communicates position with shape cues (number / filled / check / hollow) not just color, and "Step X of 5" + done badges give quiet, non-gamified progress exactly as PRODUCT.md demands.
2. **Real values, real vocabulary.** Every parameter shows a live tabular-mono number with units (`0.0°`), terms are the textbook's (∠HP, ∠VP, top/front view), and the now-bundled Atkinson Hyperlegible + IBM Plex Mono serve legibility. This is the separator between a toy and an instrument.
3. **Restraint under pressure.** Even the busiest screen (Step 4: solid + 8 labels + connectors + two projection planes) stays readable because hierarchy and the two-color HP/VP encoding hold. No decoration competes with the geometry.

## Priority Issues

- **[P1] Accent blue collides with HP projection blue, diverging from DESIGN.md.** 
  - **Why it matters:** DESIGN.md deliberately rations three distinct hues — accent ink-indigo (280), HP teal (192), VP amber (68) — so the learner can tell "the UI is guiding me" from "this is the HP top view." The build collapsed accent and HP into nearly the same blue (hue ~252 vs ~250). On a washed-out classroom projector the two become indistinguishable, and the careful eye reads it as an inconsistency.
  - **Fix:** Set `--color-accent` to ink-indigo and `--color-hp-line` to teal per DESIGN.md (VP amber already close). JS reads the tokens, so only the `:root` values change.
  - **Suggested command:** `colorize`

- **[P1] The token system is a parallel set, not DESIGN.md's.** 
  - **Why it matters:** CLAUDE.md names DESIGN.md the single source of truth and "one language, many disciplines" is a platform principle. The code ships a separate `--color-*` vocabulary with different names, a different accent hue, smaller radii, and a smaller title scale. At Module 2 the drift is cosmetic; by Module 20 it guarantees inconsistent chrome across the platform.
  - **Fix:** Reconcile the implemented tokens to DESIGN.md's names/values (or, if the code is now the intended truth, regenerate DESIGN.md to match — but PRODUCT/DESIGN are the contract, so the code should conform).
  - **Suggested command:** `extract`

- **[P1] No inline term definitions; help is thin for the primary persona.** 
  - **Why it matters:** The #1 user is a first-year who may never have seen a technical drawing. DESIGN.md specifies dotted-underline term popovers (apothem, slant height, picture plane); none exist. "Orthographic," "HP/VP," "ground line," "apothem," and "slant height" all appear undefined. This is the lowest-scoring heuristic (Help, 2) and it hits exactly the learner you optimize for.
  - **Fix:** Add the inline term-definition component from DESIGN.md and define each term on first appearance.
  - **Suggested command:** `clarify`

- **[P2] The orbit affordance is invisible.** 
  - **Why it matters:** The 3D view is drag-to-rotate but nothing says so. An anxious beginner may never rotate it, misread a projection that looks flat from the default angle, and conclude they "don't get it." Recognition-not-recall fails for the core interaction.
  - **Fix:** A one-time, dismissible "Drag to rotate" hint over the viewport when the first solid appears (respecting reduced motion), or a small persistent orbit glyph.
  - **Suggested command:** `onboard`

- **[P2] "Soft & reassuring" is under-delivered vs the anxious-learner intent.** 
  - **Why it matters:** DESIGN.md asks for generous rounding (card 16px, buttons 12px, pill sliders) and a 25px step title specifically to lower intimidation. The build is crisper (card 10px, buttons 6px) with a ~21px title, reading more "technical tool" than "patient tutor." The softness is a deliberate emotional device, not decoration.
  - **Fix:** Raise radii and the title scale to DESIGN.md values.
  - **Suggested command:** `typeset`

## Persona Red Flags

**Priya (struggling first-year, self-study — the optimized-for persona):** Reaches Step 2 and sees `∠HP`, `∠VP`, and inclination jargon with no definitions, so she stalls on what the angle physically means. She never learns she can rotate the view, so the Step 4 projection looks like flat decoration rather than a cast shadow she can walk around. The 8 labels + dashed connectors land all at once. Her real risks are the missing term definitions and the invisible orbit, not the structure.

**Mr. Rao (instructor, projecting to the back row):** The reference grids are extremely faint and the slider tracks are hair-thin, both hard to read at distance. The blue accent vs blue HP line is the worst possible pair to separate on a dim projector. Secondary text and the step title are smaller than DESIGN.md specifies, costing back-row legibility.

**Keyboard-only learner:** Largely well served — focus ring is visible, sliders take arrow keys, Back/Next/Reset are operable, and the rail is correctly non-interactive. No red flags here; this is a strength.

## Minor Observations

- Empty start leaves ~65% of the screen as a faint grid void; a ghost placeholder or a subtle arrow toward "Add solid" would orient the eye.
- The step rail now sits at the far right, so reading order (viewport → card → progress) meets progress last; defensible since you requested it, but unconventional for a progress spine.
- DESIGN.md's "current step" calls for an `--accent-soft` pill behind the rail label; the build uses only a ring.
- Slider thumb hit area (~16–20px tall) is below the 44px `--target-min` DESIGN.md requires, even though the row is 44px.
- Vertex labels can overlap the solid's own edges on denser shapes; a small leader offset or collision nudge would keep them legible.
- Disabled "Face inclination → HP" (correct for a cube) could carry the lock icon DESIGN.md specifies for disabled-by-hierarchy, so the learner reads "locked, not broken."

## Questions to Consider

- If the chrome adopted DESIGN.md's indigo accent, would HP-teal and VP-amber suddenly read as unmistakably "the drawing" versus "the guide"?
- What is the single thing that should appear the instant the first solid lands, so the learner knows the view is theirs to rotate?
- Is the progress rail earning its place on the far right, or should the learner meet "where am I" before "what do I change"?
