# Changelog

All notable changes to Module 2 (Orthographic Projection of Solids).

## 2026-07-31
- Added: `markBooted()` now posts the platform's `sim:ready` signal (ADR-078) — Module 2 was one of two legacy monoliths left out of that pass originally; it's caught up now. (`main.js`.)
- Added: "Finish lesson" button pilot — `#btn-finish` takes over the footer nav's primary slot at Step 6 exactly when `#btn-next` vacates it (same mutual-exclusivity idiom as `#btn-flatten`/`#btn-unfold`), enabled once flattened. Click posts `sim:complete` and announces "Lesson marked complete." — fixes the gap where a learner who skips a topic's auto-detected payoff moment never completes. Module 2 is the pilot; rollout to the other 18 topics is separate, not-yet-started work. (`main.js`, `src/stepper.js`, `index.html`.)
- Changed: `sim:complete` (`markComplete()`) drops its one-shot `window.__simComplete` latch — fires on every call now. Host-side confirmed to support repeated triggers; this is a platform-wide policy change (ADR-078 addendum, revised), not Module-2-specific, though Module 2 is the only place it has shipped so far. (`main.js`, `DECISIONS.md`, `RULES.md`, `PLATFORM-RULES.md`.)
- Changed: "Complete & next problem" demoted from `btn--primary` to plain `.btn--block` and relabeled "Try another problem" — Finish lesson is now Step 6's one loud action (DESIGN.md §5.1); stays the same repeatable practice-loop action underneath (exits the active problem, resets the bench, reopens the Problem Library) — no behaviour change, styling and label only. (`index.html`, `src/stepper.js`.)

## 2026-07-28
- Fixed: a follow-up audit found ADR-090's "Next sometimes does nothing" fix was incomplete — the skip loop was still bounded by a positional last-index, so a pose whose final beat drew nothing could still repaint an identical frame on the last click, and "Done" could arrive a click late. `goNext`/`renderProgress` now compare against a content-aware `computeFinalIndex()` instead (ADR-094). (`src/methodController.js`, `DECISIONS.md`.)
- Fixed: a Set-N focus chip left zoomed in made Next/Back draw beyond the visible viewport once the walkthrough crossed into a different Set — the button worked, the sheet just changed off-screen, an independent cause of the same "Next did nothing" symptom untouched by ADR-090. The active chip and camera now clear back to the whole row whenever progress moves into a new Set (ADR-094). (`src/methodController.js`.)
- Added: `sim.method.beatCount` lets `methodController.js` assert its hand-duplicated `BEAT_COUNT` against `main.js`'s `METHOD_BEAT_COUNT` at init and refuse to start on mismatch, instead of the two silently drifting under a comment-only invariant (ADR-094). (`main.js`, `src/methodController.js`, `DECISIONS.md`.)
- Fixed: the "Skip to next Set" button's own doc comment said it was hidden on the walkthrough's last Set; the code only ever disabled it, leaving a visible dead button for the entire final Set. `renderProgress` now hides and disables it together (ADR-094). (`src/methodController.js`, `index.html`.)
- Added: every Show Method beat now gets a plain-language caption ("Outline of the top view", "Projectors linking the two views", ...) — shown in a new `#method-caption` pill and read through the existing `#sim-status` announce channel on every Next/Back/Skip, so a skipped beat's absent content is no longer indistinguishable from a beat that never existed. Deliberately not a step count — ADR-089 Decision 2's counter removal stands (ADR-094). (`main.js`, `src/methodController.js`, `index.html`, `DECISIONS.md`.)
- Fixed: Show Method's cross-Set derivation line (ADR-092) drew visibly diagonal for the both-planes Set2→Set3 transition — `planMethodStages`' Set-3 pose recombined both tilt angles into one Euler from the original upright shape, which doesn't preserve a vertex's height between Sets. Added `projectSequentialBothPlanesPose` (ADR-093), used only by Show Method's own pose builder: Set 3 now reuses Set 2's own resolved pose and yaws it about world-Y (a rotation that can never touch height) instead of re-deriving from scratch — verified the connector lands bit-exact flat (`sqpyr-both`) and within float epsilon (`hexprism-both`, unequal angles). `iShape.js`/the live solid's rotation math is untouched. (`main.js`, `DECISIONS.md`.)
- Fixed: the prior session's "Show Method fully verified" claim was false — that session tested inside an MCP headless browser tab, where `document.hidden === true` fully suspends `requestAnimationFrame` (0 callbacks measured in 600ms), so the takeover's rAF-driven repaint never actually ran; nothing was really watched. Re-verified with a synchronous frame-pump standing in for rAF, confirming the beat-drawing pipeline itself was sound. (No code change — process finding.)
- Fixed: "Next sometimes does nothing" — some beats' gate passed but drew zero new segments for the current pose (e.g. no dashed generator to show on a view), repainting a byte-identical frame; `sim.method.hasContent(set, beat)` (ADR-090) now reports this per-beat from the same harvested arrays `drawMethodSheet` draws from, and `methodController.js`'s Next/Back skip past any beat it flags — every click now visibly changes the sheet. (`main.js`, `src/methodController.js`, `DECISIONS.md`.)
- Removed: Show Method's dimensions beat (ADR-089) — BIS Type-B dimensioning stays behind the live pane's own "Show dimensions" toggle; bundling it into the construction-method replay taught the wrong lesson. Beat count drops 15 → 14/Set (`METHOD_BEAT_COUNT` + its `methodController.js` twin); the now-unused `hpDimLines`/`vpDimLines`/`hpDimTris`/`vpDimTris`/`hpDimLabels`/`vpDimLabels` harvest and its two single-caller helpers were deleted with it. (`main.js`, `DECISIONS.md`.)
- Changed: Show Method's Next button no longer shows a "(N of 45)" step count — just "Next step" / "Done", matching `RULES.md`'s platform-wide step-counter-weight guidance. (`src/methodController.js`.)
- Added: Show Method's lines now stroke in one at a time (~0.2-0.4s apiece) rather than a beat's whole batch popping in as a static group (ADR-091) — reuses the existing `anim.js` tween helper, pumped by its own independent `requestAnimationFrame` loop since the sim's own loop is paused for Show Method's entire lifetime (ADR-085); Next stays clickable mid-reveal and snaps the in-flight beat to fully-drawn before advancing. Verified natively (no synthetic pump) that a full rapid walkthrough and a Back walk both run error-free; the actual real-time visual pacing needs confirming in a real foregrounded browser tab — this MCP environment cannot render one. (`main.js`, `DECISIONS.md`.)

## 2026-07-16
- Fixed: dashed hidden-edge lines could bleed through coincident visible solid lines (e.g. the Cube's front/back faces project to the identical square) — `LineSegments2` fat lines z-fought at equal depth with no deterministic winner; `buildSegments()` now biases dashed materials with `polygonOffset` and sets `renderOrder` so visible lines always paint over hidden ones, per drafting line-precedence convention.
- Fixed: Step 6's "Unfold to 3D"/"Flatten to 2D" button stayed stuck on the wrong label after a Flatten → open Compare (expanded split) → close Compare round-trip — `enterWorkbench()` forces the engine back to 3D but never told the stepper, so its own `state.flattened` latch went stale; `stepper.js` now exposes `setFlattened()` and `main.js` calls it right after the forced unflatten.
- Changed: Step 6 panel decluttered — "Unfold to 3D" moved beside its "Flatten to 2D" twin (was stranded after Dimensions), the Dimensions button dropped its blue `btn--primary` styling for the plain white `.btn` look, and its "Dimensions drawn/hidden" confirmation moved from a persistent panel badge to a transient viewport `flowNote` toast.
- Fixed: the XY / X1-Y1 reference lines on the 2D Compare sheet drifted whenever a distance slider (e.g. "Distance from HP") changed, because they were placed at the live-bbox midpoint between adjacent views instead of a fixed hinge (ADR-056) — `drawCompare()` now pins them to the analytic fold coordinates (`sheetY=0`, `sheetX=−z0`), so the lines stay put and only the geometry moves.
- Added: scroll-wheel zoom on the 2D Compare canvas (ADR-055) — zooms toward the pointer, composes with the existing drag-to-pan (ADR-054) as a screen-space lens layered on top of the fixed intrinsic scale (ADR-053) so "10 mm reads as 10 mm" still holds; resets to 1×/centred on a fresh Compare open, a canvas double-click, and a full sim reset.
- Fixed: `.wizard-toggle` (top-right chevron) was dropping 68px down the viewport because its `top` inherited `.vp-cluster`'s left-side 44px-quick-view + a11y-header clearance; now anchors to the standard `--space-3` corner inset, matching where the Compare card already assumed it sat.
- Changed: `RULES.md §5.19` rewritten to state the Module 1 (ADR-038, sheet-fixed) vs Module 2 (ADR-053, intrinsic-fixed) scale split explicitly, and document the pan/zoom exception (ADR-054/055) — user-driven view transforms are permitted as long as they compose on top of the fixed scale rather than mutating it.
- Fixed: the 2D Compare sheet's layout was lopsided — anchoring to the world origin (ADR-053) left the Side view's block, which sits a further gap to the right of Front/Top, unbalanced against them, so the left half of the card read as dead space and large distance sliders clipped the drawing off the right/top edges. `drawCompare()`'s `project()` now anchors to the intrinsic-nominal layout centre instead (ADR-054) — derived only from the solid's own size and gap, never the live bbox or distance/angle sliders, so ADR-053's scale-lock is untouched.
- Added: drag-to-pan on the 2D Compare canvas (ADR-054) — pointer-drag slides the sheet so a large-distance layout that pushes a view past the card edge stays reachable; double-click recenters. Cursor shows `grab`/`grabbing`; `touch-action: none` lets touch drag the sheet instead of scrolling the page.
- Fixed: `drawCompare()`'s 2D Compare sheet no longer rescales/re-pans the whole drawing when a distance slider (e.g. "Distance from VP") changes — the ADR-052 auto-fit measured a combined bbox of all three views, so growing the gap between them shrank everything; scale now locks to the solid's own fixed 3D size and the anchor pins to the world origin (ADR-053), so only the view the slider actually governs moves.
- Added: `drawCompare()` now draws the XY (front/top fold gap) and X1-Y1 (top-front/side fold gap) ground-line reference marks natively on the 2D Compare canvas — thin dashed `--color-ink-secondary` strokes matching standard orthographic sheet convention, ending the "intentionally not created" de-clutter gap from the 2026-07-15 ADR-052 pass.
- Added: `projectionDrawer.js` tags each projection `LineSegments2` with `segments.userData.hidden = dashed` so `drawCompare()` (and any future consumer) can read solid-vs-occluded classification straight off the object instead of relying on undocumented `LineMaterial` getter behaviour.

- Changed: `#workbench-rail` now wraps its 8 geometry-driver fields into a responsive multi-row grid instead of a single scrolling row, and reserves top clearance so the `#rail-toggle` "Hide" pill never overlaps the first row of sliders (ADR-051 amendment).
- Fixed: replaced the `#workbench-rail`'s row-wide 72px top-padding clearance for `#rail-toggle` with a `::before` generated grid item reserving just the button's own cell, so the "Hide" pill no longer wastes horizontal space above every column.
- Changed: reordered `WORKBENCH_CONTROLS` so related geometry drivers sit adjacent — distances (HP, VP) together, angles (∠HP, ∠VP) together, resting plane + turn together — instead of the prior arbitrary order.
- Changed: `#workbench-rail` now flows column-major into vertical pairs (Distance HP above Distance VP, Angle ∠HP above Angle ∠VP, Base rests-on above Turn-about-axis) instead of a horizontal ribbon, and the `::before` reserved-column spacer under `#rail-toggle` is gone — the "size" driver alone now clears the button, reclaiming the dead space it left.

- Fixed: the `size` driver's Base length + Height fields no longer stretch apart to fill their spanned 2-row cell — the wrapper is now an explicit top-anchored flex column (`justify-content: flex-start`, 16px gap) instead of a stretched block, so the two fields sit as a tight top-hugging pair like every other rail column.

- Added: `drawCompare()` now replicates the BIS SP 46:2003 Type-B dimension layer on the 2D sheet — extension/dimension lines, filled 3:1 arrowhead triangles, and the numeric CSS2D labels, all read straight off `activeProjection`'s `hp/vpDimensionGroup` and gated on the same `showDimensionsFlag` the 3D pane uses — so the flattened drawing is a full annotated replica, not just an outline.

- Changed: the 2D Compare sheet's scale switches from a fixed 140mm span (ADR-038 pattern) to auto-fit (ADR-052) — it measures the drawing it's about to paint and scales+centres to fill the card, so small solids no longer render as a speck; true size is still readable off the dimension numerals.
