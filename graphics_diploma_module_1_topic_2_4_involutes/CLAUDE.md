## The generator — one mechanism, two shapes of construction

**`involuteCirclePoint()` / `involuteContactPoint()`** (`src/constructions.js`): the involute of a
circle is a smooth closed-form parametric — a point on a taut string unwound from a circle of
radius `r` through angle `theta`. The string itself is always tangent to the circle, so it IS the
normal to the curve at the traced point (`involuteContactPoint()` gives that instantaneous
tangency point, the same role Topic 2.1's `contactPoint()` plays for a rolling circle).

**`involutePolygonArcs()`**: the involute of a regular n-gon (triangle `n=3`, square `n=4`) is
**not** a smooth parametric at all — Example 7.7's own method unwinds one straight side at a time,
each side sweeping a circular arc whose radius grows by that side's length, centred on the vertex
just left behind. This reuses the existing `arc` step primitive with no new geometry engine.

**`tangentNormalSteps()`** (duplicated from Topic 2.1, RULES §1.4): the classical fact that an
involute's normal at its traced point passes through the curve's instantaneous contact point —
same shared routine Topic 2.1's roulette family uses for the same reason.

**Why this is 3 picker entries, not fewer:** each keeps its own `id`, `principle` text (the "why
it works" shown on Verify), and its own scoped `given[]` — the circle case exposes a Roll Angle
slider the polygon cases have no use for (they are fixed-step compass constructions, not a
continuously moving generator; see `main.js`'s `play()`, which branches on `animateRoll`
presence — only involute-of-a-circle's `build()` returns one).

## Canvas size — the family default, not Topic 2.1's enlarged one

Topic 2.1 uses a `240×190` canvas, sized for its own epicycloid/hypocycloid constructions' base
circles (up to 100mm radius) — a need this topic's geometry never had. This topic's own
`INVOLUTE_BUDGET` sub-rect (`src/constructions.js`) only ever needed `180×120` worth of drawing
space regardless of which canvas it sat inside, so this topic uses the family-default `200×140`
(matching Topic 1.1) instead of copying Topic 2.1's larger one (ADR-150's own consequence note).
